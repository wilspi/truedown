Alerts on real outages, not blips.

An uptime monitor that waits for proof before it wakes you up.

TrueDown checks your sites every minute and emails you only after three failed checks in a row. A single slow response or DNS hiccup gets recorded, not alerted. It runs on the Cloudflare Workers free plan, so there's no server to patch and no subscription.

How an alert gets sent

Most false alarms come from one bad check. TrueDown treats a single failure as a data point, not an incident.

✓12:00
✓12:01
✗12:02
✗12:03
✗12:04Down email
✗12:05
✓12:06
✓12:07Recovery email
  1. Three failures in a row confirm an outage. The incident is dated from the first failure (12:02 above), not from when the alert went out.
  2. Two passes in a row confirm recovery. If a recovery check fails, the incident goes straight back to down.
  3. Late checks show as unknown. If the scheduler misses a run, the status page says so instead of showing old green as current.
  4. Mail trouble doesn't lose data. Incidents are recorded first; emails retry separately with backoff.

What's in it

Checks
HTTP and HTTPS every 1, 5 or 15 minutes. Set the expected status range, a timeout, and optionally text that must appear in the response.
Alerts
Down and recovery emails through your own SMTP provider on port 465 or 587. Any relay with SMTP credentials will do, such as Amazon SES, Postmark or Brevo.
Hourly history
Every hour is a block you can open: checks passed, response times, confirmed downtime, and each run of failures with its cause. Admins also see a response excerpt and when alerts were emailed.
Status pages
A public homepage plus separate pages at /s/your-link, each showing only the monitors you pick. Useful for giving a client their own view.
Privacy
Public pages show an endpoint's origin, never its path, query string, raw errors or response body. Shared pages are sent with noindex.
Cost
Built so 20 monitors at one-minute intervals fit within Cloudflare's free plan. Hourly aggregates mean a healthy monitor adds almost nothing to your database.

What it doesn't do

It's deliberately small. If you need any of these, a hosted service or Uptime Kuma is the better pick.

  • No multi-region checks. Every check comes from Cloudflare's network, so a regional outage elsewhere may not show up.
  • No SMS, Slack or webhook alerts yet. Email only, to one recipient.
  • No TCP, ping or DNS checks. HTTP and HTTPS only.
  • 20 monitors by default. The cap keeps a run under the free plan's subrequest limit; you can raise it after checking your Cloudflare usage.
  • No port 25. Cloudflare blocks it, so you need an SMTP relay that accepts 465 or 587.

Setup

You need Node.js 22+, a Cloudflare account and SMTP credentials. Put your settings in .dev.vars, then:

Open /#admin on your Worker, paste your admin token and add your first monitor. To use your own hostname, add a custom domain to the Worker in the Cloudflare dashboard.

cd truedown && npm install

# deploy to your Cloudflare account
npx wrangler login
npx wrangler secret bulk .dev.vars
npm run db:migrate:remote
npm run deploy

Questions

Is it actually free?

TrueDown is MIT licensed and has no paid tier. Twenty monitors checked every minute are designed to stay within Cloudflare's Workers free plan. Your SMTP provider may charge for mail, though most have a free allowance far above what outage alerts need.

Why wait for three failures? Won't I hear about outages later?

On a one-minute interval you'll hear about it about two minutes later than a monitor that alerts on the first failure. In exchange, a single dropped connection doesn't send you an email. The incident's start time is still the first failed check, so your downtime numbers stay accurate.

Can I show a status page to customers?

Yes. The homepage can list the monitors you choose, and you can create separate pages, each with its own link, title and set of monitors. A page link hides the page; it isn't a login, so anyone with the link can see that one page.

Does it need Cloudflare Email?

No. TrueDown has its own small SMTP client built on Workers sockets, so it talks to any authenticated SMTP relay directly.
